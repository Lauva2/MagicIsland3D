# 每日订单与公告栏

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

订单面板另有“小屋扩建”办事入口，点击后切换到独立的 HouseUpgradePanel，订单状态保留；规则见 [小屋扩建](HouseUpgrades.md)。

“鸡舍建造”进入独立 CoopPanel，可申请建造养殖设施，原订单进度保留。日常喂食 / 收取在鸡舍旁进行，见 [鸡舍养殖](Animals.md)。

岛屿办事处位于农场右后方，门前右侧设公告栏，门口留出石板通道。玩家走近后点击公告栏，打开今日订单；建筑内暂未开放。公告栏只响应首次点击，不对身后的农田执行操作。

## 玩法

- 每天发布一单，原作物订单要求交付 1–3 个同类作物；面板显示物品、所需数量、背包数量和金币奖励。
- 春季收购芜菁；夏季收购番茄或玉米；秋季收购芜菁或玉米；冬季从三种作物中收购库存。冬季播种规则不变，可以交付之前保存的收成。
- 默认芜菁每个 40 金币、番茄 75、玉米 130，高于商店售价；一次交付全部需求，背包保留多余作物。
- 建成鸡舍后，从次日起加入鸡蛋 ×2（70 金币）、煎蛋 ×1（50 金币）、蔬菜蛋汤 ×1（90 金币）三种全年订单，原作物仍在随机池中；建造当天订单不变。详见 [养殖与料理订单](AnimalOrders.md)。
- 数量不足、金币无法容纳奖励、已交付或正在操作时不再次扣物品或发金币。订单交付不计作商店出售，不推进“出售”新手任务。
- 订单当天有效，睡觉或调试“下一天”后刷新；未完成订单不会累计或扣罚。完成当天订单后等待次日新单。
- 公告栏面板打开和加载时暂停时钟，禁用移动和场景操作，拦截其他弹窗与跨日；点击关闭或按 Esc 返回游戏。

## 框架与资源

`GameManager` 调度 `OrderManager` 初始化、建筑加载、每日刷新、交付和睡觉时统一保存。`OrderState` 管理纯规则，使用保存的正整数种子、总天数和当天订单池标记确定订单，先检查再同步提交物品、金币和交付标记，事件重入不能重复付款。

| 资源 | 路径 | AA 地址 |
| --- | --- | --- |
| 订单配置 | `Assets/Config/OrderCatalog.asset` | `OrderCatalog` |
| 办事处与公告栏 | `Assets/Art/Prefabs/Buildings/OrderHall.prefab` | `OrderHall` |
| 订单面板 | `Assets/Art/Prefabs/UI/OrderPanel.prefab` | `OrderPanel` |

`OrderCatalog` 配置稳定订单 ID、CropId 作物映射或 ItemId 物品引用、RequiresCoop 条件、季节、数量范围、单个奖励和建筑地址。启动校验物品类型、四季非鸡舍订单覆盖、数量和高于物品收购价格的奖励。OrderHall 的公告栏带 `OrderBoard` 组件和子碰撞体；替换模型时保留此交互标记。

`UIManager` 按 `OrderView.Layer` 将面板放到 PopUp，`OrderController` 更新 `OrderModel` 并调用 Manager，View 只显示 TMP 文本、图标和按钮。中文使用 IslandUI 字体。退出时释放建筑 AA 实例、面板和系统引用。

编辑器配置仅创建缺失的配置、建筑、材质及面板，不覆盖已编辑资源。日常修改可直接在 Inspector 调整，执行 `Magic Island > Configure Prototype Addressables` 注册资源。

## 存档

版本 8 引入订单，当前版本 25 保存订单种子、总天数、配置 ID、物品 ID、数量、奖励、交付标记和 CoopOffersUnlocked 当天池标记，与背包、金币、养殖和任务一起写入。加载校验订单与天数、配置、鸡舍状态和确定性生成结果一致；当天读档不重新抽单，已交付订单不再支付。

交付后在睡觉时统一保存。写入失败保留当前运行的交付结果并提示重试，重复交付仍无额外奖励；后续保存、跨日或返回主菜单会再次保存。版本 1–7 按原有规则迁移，再为当前日期创建未交付订单，不改已有库存、金币或版本 7 的任务领奖标记。

订单生成依赖 OrderCatalog 和每季天数；改动已保存订单对应规则可能使旧存档校验失败，沿用备份恢复机制。

版本 20 及以前补未启用鸡舍订单池的标记，不改变已存在的当天订单。已有鸡舍从迁移后的次日起启用新池，不因读档刷新。详见 [养殖与料理订单](AnimalOrders.md)。

## 验证

- `Tools/VerifyOrders.cs`：2747 项断言，覆盖确定性、季节、数量、交付原子性、重复与事件重入、奖励溢出、恢复独立性、异常数据和版本 1–7 迁移。
- `OrderFlowVerification.Run`：隔离 Unity 项目使用打包 AA，检查建筑、公告栏射线及距离、PopUp/MVC、中文与布局、弹窗暂停、交付及保存失败恢复、读档、次日刷新、无效数据拒绝、版本 7 迁移及资源清理。

优质鸡蛋可替代普通蛋，料理和订单优先使用普通蛋；品质、双产物收取与版本 23 迁移详见 [优质鸡蛋](QualityEggs.md)。
