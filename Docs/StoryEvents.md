# 好感度事件与食谱解锁

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

走近林舟交谈，日常对话面板增加往事按钮。达到好感度要求后点击按钮进入专属对话；事件中的送礼和往事入口禁用，逐句推进或 ESC / 关闭退出。

| 事件 | 好感度 | 前置事件 | 完成结果 |
| --- | ---: | --- | --- |
| 小岛往事 | 30 | 无 | 记录已听完往事 |
| 朋友的食谱 | 70 | 小岛往事 | 解锁蔬菜浓汤 |

事件只在完整推进完最后一句后完成。中途退出，包括显示最后一句后退出，均不记录完成，下次从第一句开始。不会自动打断日常对话，首次见面介绍照常；条件不足时按钮显示所需好感度。两段事件各可完成一次。

## 食谱与制作

蔬菜浓汤消耗芜菁、番茄、玉米各 1，产出 1 碗，在背包中食用恢复 50 体力，恢复不超过体力上限。料理面板第三张卡片显示三种食材库存、恢复量、锁定状态和条件。仅达到 70 好感度仍不能制作，须完成“朋友的食谱”。

制作先检查解锁及全部食材，在临时背包模拟全部扣料后检查产物容量，再一次提交并通知。最后一份任意食材腾出的格子或已有食物堆叠可容纳产物；缺料或空间不足均不扣除任何物品。原有两种食谱保持默认开放。

## 管理与资源

`StoryEventManager` 管理事件配置、可用条件和完成记录，`StoryEventState` 为纯 C# 规则。食谱解锁从已完成事件推导，和完成标记同时生效，不保存独立、可能冲突的解锁列表。事件不发放实物、不消耗好感度、金币或体力，不触发农务任务。

`DialogueManager` 持有当前事件 ID 和固定台词快照；`GameManager` 调度入口、距离、结束结算、保存及清理。`CookingManager` 继续负责制作；`FoodManager` 继续负责食用。

| 资源 | 路径 | AA 地址 |
| --- | --- | --- |
| 事件配置 | `Assets/Config/StoryEventCatalog.asset` | `StoryEventCatalog` |
| 料理配置 | `Assets/Config/CookingCatalog.asset` | `CookingCatalog` |
| 事件对话面板 | `Assets/Art/Prefabs/UI/DialoguePanel.prefab` | `DialoguePanel` |
| 五种食谱滚动面板 | `Assets/Art/Prefabs/UI/CookingPanel.prefab` | `CookingPanel` |

沿用 PopUp 层、MVC、中文 TMP 和奶油白 / 草绿色主题。事件加载和显示遵循原有对话范围、动作锁及模态暂停规则，完成时再次检查距离。取消或加载失败不完成事件。

事件配置包含稳定 ID、NPC ID、好感度、前置事件、食谱奖励和 1–16 句台词。前置事件须排在前方、属于同一居民，阈值不得超过后继事件；食谱的 RequiredEventId 与事件的 RecipeId 必须双向匹配。未知 ID、重复奖励、循环前置、非法阈值或空台词拒绝启动。编辑器只补缺失配置与食谱，对旧面板一次补齐按钮和第三张卡片，完整布局不重复覆盖。

## 存档

版本 14 新增 `StoryEvents`，按配置顺序保存 ID 和 Completed。事件完成后在睡觉时统一保存；食谱权限由相同完成记录恢复。写盘失败保留本次运行的完成和解锁结果，在料理面板“保存进度”或返回主菜单时重试，不重复结算事件。

版本 1–13 迁移补未完成事件，保留世界、已见面、好感度和送礼日期；不会按历史好感度自动完成或解锁，高好感度旧档需先听完往事再领取食谱。读取严格检查数量、ID、顺序、完成阈值与前置记录，异常数据拒绝整份存档。对话当前句和事件会话不保存。

## 验证

`Tools/VerifyStoryEvents.cs` 检查 0–100 好感度边界、前置顺序、单次原子解锁、重入、深快照、非法记录、三食材与容量组合、恢复量和版本 13 迁移。

`StoryEventFlowVerification.Run` 在隔离 Unity 项目构建并运行 AA，验证按钮、距离、模态暂停、取消 / 最后一句完成、保存失败重试、读档、防重复、锁定 / 解锁食谱、制作 / 食用、旧档迁移、非法完成记录及中文排版。
