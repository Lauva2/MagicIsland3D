# 储物箱

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

农田前方偏左新增一个固定储物箱。走近后点击打开 `StoragePanel`，按 ESC 或关闭按钮退出。第一版没有制作、自由摆放、多个箱子或费用。

## 存取规则

- 默认 18 格，物品每格上限沿用 ItemCatalog（当前为 99）。上方是随身背包，下方是箱子。背包固定三排十格，未解锁位置显示锁图标；超过三十格的旧档通过翻页访问。箱子容量仍可配置为 1～36，超过其视口时使用滚轮。
- 点击任意一侧格子后，操作按钮切换为存入或取出。可转移一个或当前选中格子的整组物品。
- 目标先补同类未满堆叠，再使用空格；源端只扣选中的格子，其他同类堆叠保持不变。
- 原有“存入／取出一个”和“存入／取出整组”按钮仍要求选定数量全部放下；空间不足时不转移。拖拽、Shift 快捷转移和“存入同类”支持部分转移，剩余物品保留在来源库存。
- 两边库存一起提交后才通知 UI。事务期间防止重入，避免只改一边或重复转移。
- 空格、非法格子和数量不产生变动。距离太远、动作进行中、未打开面板时不能存取。
- 不消耗体力或金币，不触发任务的收获、出售行为。箱内物品不计入背包；种子、交易、订单和工具升级仍只读取背包，需要先取出物品。
- 面板加载和打开期间暂停时钟与天气表现，禁止场景工具动作；与背包、商店、睡觉、订单和升级面板互斥。

## 架构与资源

`StorageManager` 负责储物状态、AA 箱子实例、存取和反馈。`StorageState` 使用独立 InventoryState 保存箱子库存，调用选定格子的原子转移方法。`GameManager` 统一调度初始化、交互、保存和退出清理，`UIManager` 加载 `StoragePanel`，其 MVC 控制器绑定按钮并显示两边库存。

| 资源 | 路径 | AA 地址 |
| --- | --- | --- |
| 配置 | `Assets/Config/StorageConfig.asset` | `StorageConfig` |
| 箱子 | `Assets/Art/Prefabs/Buildings/StorageChest.prefab` | `StorageChest` |
| UI | `Assets/Art/Prefabs/UI/StoragePanel.prefab` | `StoragePanel` |

StorageConfig 配置容量（1–36）和模型地址。箱子带 StorageChest 标记及碰撞体，位置由农田尺寸计算为 `(-1.5, 0, -FarmSize * 0.6 - 2.2)`，避开农田、床、商店、公告栏、工作台和已有资源节点。固定箱子位置不单独存档。

面板属于 PopUp 层，中文 TMP 字体、奶油白 / 草绿 / 暖沙色，与已有 UI 一致。编辑器只创建缺失配置和预制体，保留已有模型、参数和布局；AA 地址与 UI 预制体名称一致。

## 存档

版本 11 新增 `Storage`，按格子保存 ItemId 和 Quantity。成功存取只改变运行中的两边库存，睡觉时一起写入快照；关闭面板不重复转移。面板不提供手动保存，返回不保存，直接退出只保留最近成功睡觉的快照。

版本 1–10 迁移补空箱子，不搬动现有背包、不赠送物品，保留农田、任务、订单、采集、工具等级、金币和体力。箱子格子数必须匹配配置，格子缺失、未知物品、负数量、超堆叠上限及空格携带物品 ID 时拒绝恢复；先在临时库存校验，再恢复世界。修改容量可能导致旧存档不兼容。

## 验证

`Tools/VerifyStorage.cs` 覆盖双向存取、数量与容量边界、总量守恒、指定格子扣除、同类堆叠、单次通知、事件重入、深快照、非法恢复和版本 1–10 迁移。

`StorageFlowVerification.Run` 在独立 Unity 项目中构建并运行 AA，检查箱子和面板 MVC、距离 / 射线 / UI / 动作锁、两种存取按钮、空间不足保护、模态暂停、睡觉时统一保存失败与重试、精确读档、非法物品拒绝、版本 10 迁移、退出清理和中文布局。

## 快捷存取

- 左键将物品拖到另一块库存的空格或同种物品上，按目标格子的空间移动或合并。不同物品不交换，目标堆叠已满时拒绝转移；超出目标堆叠上限的部分留在来源格。
- `Shift + 点击`尽量转移选中整组，先补对面同种未满堆叠，再填空格，空间不足时只移动可以放下的数量。成功后清空选中项并睡觉时统一保存。
- “存入同类”以操作开始时箱内已有的稳定 ID 为匹配集合，依次处理背包中符合的格子，填同种堆叠和空格。没有匹配物品或没有可用空间时不改库存。普通鸡蛋与优质鸡蛋分别匹配，未转移的物品保留在背包。
- `InventoryState.TryTransferAvailableSlotTo` / `TryTransferMatchingTo` 先在两份临时库存计算完整结果，再一起提交两边数组。保留原库存对象和只读集合；在任一库存通知前完成全部变化并更新两边 ReorderVersion。批量操作只通知每个库存一次，期间拒绝重复存取和整理。累计搬运数量使用 long。
- `StorageState` 控制存取规则与事务，`StorageManager` 控制拖拽快照、存取请求、反馈与待保存状态；GameManager 检查面板、距离及动作锁，统一保存。`StorageController` 通过 `InventorySlotInput` 处理拖放和 Shift 点击，预览作为 StoragePanel 的预制体子对象，不拦截落点射线。
- 拖拽只显示预览，不提前扣除物品；松开到面板外、同一块库存、锁定格子、关闭面板、失去焦点或来源失效时取消。拖拽期间禁用其他存取、批量存入、保存和翻页。存取提交期间保护关闭面板、跨日及返回菜单。
- 背包初始十格，第二、三排锁定，每次升级增加十格并即时解锁。旧档翻页将可见格子映射到真实库存索引；跨页拖放、Shift、数量和升级等级沿用原库存，不截断物品。锁定格子不能作为来源或目标。
- 白天存取只修改两边运行状态，不创建待保存错误提示；睡觉时保存全部存取结果。沿用现有版本 25，拖拽、页码和提示不写入存档。
- StorageShortcutSetup 对现有 StoragePanel 一次迁移布局和组件，后续初始化保留编辑。仍使用同名 AA 地址、MVC、PopUp 层与中文 TMP，没有新增配置或面板。

`Tools/VerifyStorageShortcuts.cs` 验证指定落点、部分合并、不同物品拒绝、锁定容量、精确 ID 匹配、批量原子通知及重入保护、超过 int 的总量，以及各种新旧背包容量下的连续随机存取守恒。`StorageShortcutFlowVerification.Run` 验证实际 AA 面板、EventSystem 拖放与 Shift 路由、预览、取消和锁格、部分转移、同类批量操作、保存失败重试、无经济／体力／收获变化、旧档跨页索引与完整读档。
