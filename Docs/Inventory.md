# 物品与背包

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

物品配置通过 ConfigurationManager 从 AA 地址 `ItemCatalog` 加载。InventoryManager 在 GameManager 初始化世界之前创建背包，初始种子数量来自 GameConfig。

## 配置

- `Assets/Config/ItemCatalog.asset`：稳定物品 ID、名称、类型、图标、图标颜色、堆叠上限和描述。当前包含芜菁、番茄、玉米的种子及成熟作物，以及木材、石料两种材料，每格最多 99 个。图标暂用不同颜色的圆角色块。
- `Assets/Config/GameConfig.asset`：InventorySlots 默认 10，可配置 6～36；SeedItemId / HarvestItemId 指定默认种子和收获物，其他品种由 CropCatalog 定义。
- 稳定 ID 用于规则和数量查询，显示名称可修改；UI 预制体的 AA 地址仍等于预制体名字。

## 数据与规则

- InventoryState 是纯 C# 数据，提供只读格子快照、数量查询和全部成功或全部失败的添加／消耗。
- 添加时先填已有同类堆叠，再占空格；消耗可跨堆叠，并在数量归零时释放格子。
- 数量不足、容量不足、未知 ID、非正数量都会拒绝操作，不改变已有物品，也不发出变化事件。
- FarmManager 通过 FarmActions 协调农田与背包：播种成功消耗一颗种子，收获成功加入一个作物；背包满时保留成熟作物。即使没有空格，只要已有作物堆叠还有空间，也可以收获。
- GatheringManager 协调资源次数、体力与材料产出。每次操作前要求空间容纳完整产出，失败不改变资源或体力，最后一下加入整份材料。HUD 显示木材和石料数量，材料不能用于播种。
- FarmState 只保存农田状态，不再保存独立的种子／收获计数；HUD 数量从真实背包读取。

## UI MVC

- `InventoryPanel.prefab` 位于 `Assets/Art/Prefabs/UI`，由 UIManager 按 AA 地址 `InventoryPanel` 实例化。
- InventoryModel 保存格子和详情数据；InventoryView / InventorySlotView 显示组件；InventoryController 绑定选择／关闭事件，并订阅背包变化，关闭游戏时解除绑定。
- B 键或 HUD 的背包按钮打开，B / Esc / 关闭按钮收起。打开期间停用角色移动、工具交互和镜头缩放；关闭后恢复。
- 背包固定三排，每排十格。点击已解锁格子显示物品名称、描述、数量和堆叠上限；未解锁格子显示锁图标并禁用操作。超过三十格的旧档通过翻页访问，每页仍为三排十格。
- 种子详情还显示适宜播种季节及当前是否适宜。可选择非当季种子，实际播种时检查季节；错误季节不消耗种子或体力。详情预制体已扩展高度，新增文案使用已烘焙的 TMP 中文字体。
- 选择 CropCatalog 支持且有库存的种子后，可点击“用于播种”，关闭背包并切换到对应种子的播种工具；HUD 显示当前种子。工具动作进行中时拒绝切换，保留背包并提示。
- 返回主菜单先确认丢弃当天未睡觉进度，不保存，随后释放 InventoryPanel 并清理运行时背包。“加载游戏”恢复原有格子和数量，“新游戏”使用初始物品。商店可购买种子、出售作物；物品拖拽和拆分见下文，当前未接入丢弃。

## 检查

- `Tools/VerifyFarmState.cs`：509 项农务与实际物品流转断言。
- `Tools/VerifyInventory.cs`：1515 项背包／农务断言，包括跨堆叠、失败操作、数量守恒和满背包保留作物。
- `GameFlowVerification.Run`：实际 AA 构建与 MVC 进入／返回流程，包含背包按钮、详情、输入启停、播种／收获、容量保护及新游戏重置。

储物箱使用独立 InventoryState。InventoryState.TryTransferSlotTo 按选定格子原子转移，源与目标一起变动再通知；StorageManager 协调存取和保存。箱内数量不计入种植、买卖、订单和升级库存。详见 [储物箱](Storage.md)。

新增 Food 分类。背包选择食物显示“食用一个”，详情显示恢复量和当前体力，成功后更新运行状态，睡觉时统一保存。体力已满禁用食用，食物不能播种；箱内食物需先取出。详见 [烹饪与食物](CookingAndFood.md)。

新增 Fish 分类，沙丁鱼和鲈鱼沿用 99 堆叠、背包与储物字段，可在商店出售或作为料理食材；原鱼不能直接食用、播种或送礼。两种鱼类成品属于 Food，可食用、送礼及储物。详见 [钓鱼](Fishing.md)和[鱼类料理](FishCooking.md)。

新增 Placeable 分类（枚举值 6），木栅栏、石板路、庭院灯沿用 99 堆叠和储物规则。背包选择成品显示“摆放一个”，关闭背包进入网格预览；确认才扣除一件，取消保留物品。右键回收先检查背包容量。成品不能播种、食用或送礼，详见 [制作与摆放](CraftingAndPlacement.md)。

室内背包仍使用同一库存，可食用料理和摆放家具，进度仅在睡觉时保存；农场装饰摆放按钮禁用，带回农场后可以继续摆放。家具在室外禁用摆放，带入小屋后启用。区域与位置保存规则见 [玩家小屋](Housing.md)，家具见 [室内家具](Furniture.md)。

饲料使用 Material，鸡蛋使用追加的 AnimalProduct（值 8），库存与其他物品一样堆叠和保存。鸡蛋不显示播种、食用和摆放按钮，出售在商店“养殖用品”面板进行；饲料在鸡舍使用。见 [鸡舍养殖](Animals.md)。

背包可在商店扩容，每次增加十格，新游戏从十格起步，旧档保留实际基础容量。升级、动态格子与版本 25 迁移见 [背包扩容](InventoryUpgrades.md)。

## 一键整理

- 背包右上角“整理”按钮沿用 `InventoryPanel` 的 AA 加载和 MVC，`GameManager.SortInventory` 调度 `InventoryManager`，规则由纯 C# `InventoryState.TrySort` 执行。
- 先合并相同稳定 ID 的零散堆叠，每格遵守物品的 MaxStack；再依次排列种子、作物、材料、工具、食物、鱼、农场装饰、家具、养殖产物。同类型按 ID 的 Ordinal 顺序排列，空格集中到末尾。普通鸡蛋与优质鸡蛋 ID 不同，独立整理。
- 总量使用 long 累计；先在临时数组完成排列，再原地提交。保留原有 InventoryState、只读格子集合和实际容量，不改变扩容等级、金币、体力、农田和经营结算。
- 每次成功整理都递增运行时 ReorderVersion，再通知界面；InventoryController 在刷新格子前清空选中项，避免误食用、误播种或误摆放。空背包与已整理背包同样安全处理。
- 仅在正常游戏且背包可见时执行，转移或整理通知期间拒绝再次整理，提交期间保护其他背包操作和场景切换。
- 整理只改变运行中的顺序，睡觉时统一保存，背包不提供手动保存或重试按钮。沿用版本 25 的格子存档，加载时恢复保存的确切排列，运行时选择版本和提示不写入存档。
- `InventorySortSetup` 只补缺失的按钮引用，后续初始化保留已有布局和编辑。按钮与提示使用 IslandUI 中文 TMP 字体。

验证：`Tools/VerifyInventorySorting.cs` 覆盖新档和旧档的 10 / 12 / 20 / 22 / 30 / 32 / 56 格、各种类型和堆叠上限、超过 int 的总量、满背包、空背包、数量守恒、确定顺序、幂等与转移保护；`InventorySortFlowVerification.Run` 验证实际 AA 按钮、选择清空、提交保护、保存失败重试、扩容后的精确读档及中文布局。

## 拖拽与拆分

- 左键拖拽非空格，移动整组物品。放到空格时整组移动；放到相同 ID 的物品上时尽量合并，超过 MaxStack 的部分留在原格；放到不同 ID 的物品上时交换完整堆叠。普通鸡蛋与优质鸡蛋按不同物品处理。
- 右键点击数量至少为 2 的格子，将向下取整的一半移到第一个空格，奇数多出的一件留在原格。数量不足或没有空格时显示提示，原有物品与选择保持不变；已有同种堆叠不替代拆分所需的空格。
- 拖拽期间显示跟随鼠标的物品预览和源格提示，原库存保持不变。松开到面板外、关闭背包、失去窗口焦点或源物品发生变化时取消。放回原格、目标堆叠已满或其他指针的拖放也不会移动物品。
- `InventorySlotInput` 接收 EventSystem 拖放和右键事件，`InventoryController` 协调拖拽预览和请求，`GameManager` 统一检查操作状态并调用 `InventoryManager`。Manager 保存源格快照及运行时版本，纯 C# `InventoryState.MoveSlot` / `SplitSlot` 完成两格原子提交。
- 正式背包格子的拖拽事件由格子处理，三排完整显示无需滚动；大容量旧档使用翻页按钮。拖拽预览的 CanvasGroup 不拦截射线。拖拽期间禁用整理、保存、食用、播种、摆放和翻页；结束或取消后恢复。储物箱和送礼格子继续使用其原有操作。
- 成功后递增 ReorderVersion，在物品通知时清空选中项；白天只更新运行状态，睡觉时统一保存。取消和拒绝操作不增加版本、不改变数量、不触发睡觉时统一保存。
- 沿用 AA 地址 `InventoryPanel`、PopUp 层、中文 TMP 和现有十格起步、每次升级增加十格的容量规则。实际格子顺序仍保存在版本 25 中；拖拽预览、指针、选择和反馈属于运行时数据。编辑器初始化只补缺失组件和预览，保留已有编辑。

验证：`Tools/VerifyInventoryEditing.cs` 检查精确移动、满堆叠、部分合并、不同物品交换、奇偶拆分、单件／空格／满背包拒绝、超过 int 的总量、10 / 12 / 20 / 22 / 30 / 32 / 56 格随机连续操作及通知期间的操作保护。`InventoryEditFlowVerification.Run` 通过实际 AA 面板验证 EventSystem 子节点路由、预览不遮挡落点、取消与指针归属、来源失效、选择清空、保存失败重试、扩容后的绑定与精确读档、食用、退出清理和中文布局。

## 三排与锁定格子

- `InventoryPanel` 固定三十个物理格子，网格十列、三排，三排全部位于视口内。新游戏只创建十格实际库存，第二、三排以灰色底和锁图标显示，不会计入可用容量。
- 第一次升级实际容量增加至二十格，立即解锁第二排；第二次增加至三十格，解锁第三排。已解锁空格可以正常选择和接收拖放，锁定格子拒绝点击、拖拽起点、拖放目标和右键拆分，落到锁定格子会取消拖拽并保留原库存及选择。
- 锁图标使用 `InventoryLockGraphic` 绘制，依赖 CanvasRenderer，不拦截射线；文字继续使用中文 TMP。布局及图标由 `InventoryGridSetup` 一次迁移到现有预制体，后续初始化保留编辑。
- 旧存档可能保留十二格基础容量或更大的自定义基础容量。实际库存、物品位置、数量及升级等级全部保留。实际容量超过三十时显示翻页按钮，每页三排十格，最后一页未使用的位置保持锁定；控制器将页面格子映射到真实库存索引，选择、食用、拖放与拆分均使用真实索引。翻页清空选择，拖拽期间不能翻页。
- 沿用 AA / MVC、版本 25 和现有扩容价格。StoragePanel 的背包区域同样采用三排十格、锁定状态和旧档翻页，并支持跨库存拖拽与 Shift 快捷存取；送礼面板保留其原有格子布局。

`InventoryGridFlowVerification.Run` 验证实际 AA 预制体的三排十列、全部格子位于视口内、十／二十／三十格的即时解锁、锁定交互保护、中文字体和重复初始化保留资源，并验证五十六格旧档的跨页索引、品质拆分、食用、拖放及完整读档。
