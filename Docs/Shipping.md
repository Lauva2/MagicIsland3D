# 出货箱与隔夜售卖

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

小屋门口左侧的出货箱通过 AA 地址 `ShippingBox` 加载。走近后鼠标点击，打开 PopUp 层 MVC 面板 `ShippingPanel`；打开、加载和提交时暂停场景输入及游戏时钟，ESC 关闭。

## 存入与取回

- 接受有正售价的农作物、鱼类，以及 AnimalConfig 指定的普通 / 优质鸡蛋。种子、材料、料理和家具不可出货。
- 上方背包保持三排、每排十格，未解锁格显示锁。旧档超过 30 格时分页，真实容量和物品保留。
- 下方出货箱固定 18 格，同一物品按原堆叠上限合并。点击格子后可放入 / 取回一个或整组，容量不足时整次失败，不转移部分物品。
- 放入不立即给金币；睡觉前可取回，预计收入随箱内物品更新。成功存取仅更新当前两边库存，睡觉时统一保存，面板不提供保存按钮。
- 售价统一来自 ItemCatalog（农作物 / 鱼）与 AnimalConfig（鸡蛋），不维护重复价格配置。默认普通蛋 25、优质蛋 40 金币，分别堆叠和计价。

## 跨日结算

GameManager 在推进农场日期之前调用 ShippingManager 的结算规则，统一清空出货箱并增加金币，然后完成农田、动物等次日状态与日报。出货收入计入刚结束那一天的经营收入，日报滚动明细列出物品、数量、成交单价和金额；次日产物仍由原系统提供。

一次结算先检查全部收入是否能进入金币余额，成功后提交箱子、金币、结算日期，再通知观察者。同一天不能重复结算，空箱也记录结算日期；金币溢出时保留全部物品、金币和日期，提示取回或消费后再休息。成功售出的农作物更新新手出售任务；放入箱子、取回和失败结算均不算出售，鱼与鸡蛋不增加作物出售任务进度。

待查看日报会阻止再次睡觉和出货操作。日报确认只关闭报告，不写盘、不重新售卖。若睡觉保存失败，当前运行已清箱和收款，只能在日报重试同一睡觉快照；返回不保存，退出后以最后一次成功睡觉存档为准。

## 架构与存档

- `ShippingManager` 持有 AA 模型句柄，初始化、释放、交互反馈和出货状态。
- `ShippingState` 使用现有背包 / 储物原子转移规则，管理资格、报价和结算日期；规则不依赖 Unity。
- `ShippingConfig` 经 ConfigurationManager 使用 AA 同名地址加载，指定模型地址及小屋旁的位置；当前共 24 份 AA 配置。
- `UIManager` 使用 AA 同名地址加载 ShippingPanel；Model 保存显示数据，View 引用 TMP / 格子 / 按钮，Controller 绑定和解绑操作；当前共 26 个 UI 预制体。
- 存档版本 26 同时保存出货箱 18 个格子、最近结算日期及日报成交明细。版本 1–26 迁移为空箱，不补发金币、不改变旧日报收入。
- 读档校验容量、堆叠上限、物品资格、日期和日报金额；异常记录拒绝读取，沿用备份恢复机制。成交价格以日报记录为准，不随之后配置变化重算。
- 编辑器仅补齐缺失资源；日报增加明细区域为一次性迁移，重复配置保留完整预制体的人工编辑。

## 验证

`Tools/VerifyShipping.cs` 检查类型限制、容量、当天取回、品质计价、观察者一致性、重入、金币溢出、迁移与存档校验。

`ShippingFlowVerification` 使用打包 AA 验证真实面板、中文 TMP、锁格、场景距离与 UI 拦截、存取失败重试、隔夜日报、未结算 / 已结算读档、旧档升级、异常记录、资源清理与新游戏重置。日报、储物快捷操作、背包扩容和基础游戏流程用于回归验证。
