# 养殖与料理订单

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

鸡舍建成后，从次日开始，公告栏的每日随机订单池加入鸡蛋和两道鸡蛋料理。建造当天的订单不变，仍每天一单；新池包含原作物订单和新增订单，按季节从可用条目中选择。三种新增订单全年供应，无需先买鸡或收蛋来解锁。

| 需求 | 数量 | 默认单价 | 总奖励 |
| --- | ---: | ---: | ---: |
| 鸡蛋 | 2 | 35 | 70 金币 |
| 煎蛋 | 1 | 50 | 50 金币 |
| 蔬菜蛋汤 | 1 | 90 | 90 金币 |

原料来自 [鸡舍养殖](Animals.md)，成品通过 [鸡蛋料理](EggCooking.md) 制作。箱内物品需先取到背包；每天只有一份订单，未完成不累计或扣罚。

## 交付与 UI

继续使用建筑前公告栏和 AA 加载的 PopUp 层 MVC `OrderPanel`。面板显示物品名称、图标、需求、背包库存、金币与当天状态；按钮统一为“交付全部物品”。没有增加面板或 AA 地址，既有办事处、扩建和鸡舍入口保留。

交付一次扣除完整需求，保留多余物品，同时提交奖励和已完成标记，再通知库存、金币和 UI。缺料、金币上限、已交付、超出范围或交付重入时不扣物品、不发奖励。交付料理不等于食用，不恢复体力；任何订单都不计入出售或收获作物的新手任务。

交付后在睡觉时统一保存。保存失败保留完整运行结果并提示，重复交付不再发奖；通过再次保存进度或返回菜单重试保存。提交期间拦截关闭、返回菜单和跨日，避免通知回调打断事务。

## 配置与确定性

AA `OrderCatalog` 新增三条配置，稳定 ID 为 `egg_daily`、`fried_egg_daily`、`egg_vegetable_soup_daily`。原作物保留 CropId 映射，新条目直接使用 ItemId，并设置 RequiresCoop。每条只能指定 CropId 或 ItemId；当前支持 Crop、AnimalProduct、Food，种子、材料和鱼类被拒绝。保持四季至少有一条不依赖鸡舍的订单。

`OrderManager` / `OrderState` 管理订单；`GameManager` 在统一跨日结算中，根据鸡舍已建成状态启用下一天的订单池。订单仍由正整数种子、总天数、季节和当天池标记确定，不读取库存或当前喂食状态，不因打开公告栏或读档重新抽单。编辑器仅补缺失条目，保留已编辑费用、季节、数量和已有资源 GUID。

## 存档

版本 21 引入 `SavedOrder.CoopOffersUnlocked`，当前版本 25 保留该字段，保存生成当天订单时使用的池，与订单参数、已交付标记、养殖、库存和金币一起保存。恢复时按该标记重新校验确定性结果；已启用的池需要鸡舍已建成且日期至少为第二天。已有鸡舍但标记为 false 是合法状态，表示建造当天或迁移后的旧订单。

版本 20 及以前的当天订单标记补 false，仍使用原作物池校验；原 ID、数量、奖励、交付状态、库存和金币保持不变。版本 20 已保存的鸡舍、鸡、喂食与待收产物全部保留，次日进入新池；更早版本仍按既有规则补空养殖状态。已交付旧单不会变成未完成，也不会再次发奖。修改已有订单规则仍可能让对应旧档校验失败，沿用备份恢复机制。

## 验证

`Tools/VerifyAnimalOrders.cs` 覆盖多种种子与多个季节 / 年份的原池保持、解锁池生成与读档一致、三种固定奖励、缺料 / 溢出 / 重入 / 已完成保护、无效恢复原子性、版本 8–20 的未完成和已交付旧单迁移、鸡舍与池标记交叉校验。原 `VerifyOrders` 继续覆盖版本 1–7 迁移。

`AnimalOrderFlowVerification.Run` 在隔离 Unity 工程构建 AA，走通公告栏建鸡舍、两次喂食产蛋、收集、真实料理按钮、三种订单交付及读档。验证建造当天保留旧单、实际缺字段的 v20 存档迁移、缺料 / 金币上限 / 距离 / 模态、保存失败与重试、通知重入、70 / 50 / 90 奖励、中文排版、错误池 / 无鸡舍拒绝、新游戏和资源清理。

优质鸡蛋可替代普通蛋，料理和订单优先使用普通蛋；品质、双产物收取与版本 23 迁移详见 [优质鸡蛋](QualityEggs.md)。
