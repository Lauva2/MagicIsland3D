# 存档系统

`SaveManager` 负责本地存档文件、校验和备份；`GameManager` 调度保存和恢复，不让 UI 或场景组件自行启动流程。

## 保存内容与入口

- 单存档，版本号目前为 19；JSON 保存日期、当天天气及天气随机种子、时刻（含部分分钟）、体力、当前种子选择、农田尺寸及每格作物 ID 和耕作/种植/浇水/生长状态、背包各格的物品 ID 和数量、角色区域和位置、金币，以及任务 ID、进度和领奖标记、当天订单种子、配置 ID、物品、数量、奖励和交付标记、采集节点 ID、剩余操作次数和恢复总天数、斧头与镐子的升级等级、储物箱各格物品、NPC 的 ID / 已见面标记、好感度和最后送礼总天数，以及事件 ID / 完成标记、NPC 日程的 ID / 路线距离、装饰的 ID / 物品 / 位置 / 朝向。
- `Day` 保存游戏总天数，CalendarManager 按 SeasonConfig 推导年份、季节和季节内日期，不增加独立日期字段。旧存档迁移后使用同一推导规则；修改每季天数会重新解释旧存档日期。已种作物在非适宜播种季节仍可恢复并成长。
- 主菜单“新游戏”创建初始状态；“加载游戏”从磁盘读取并校验，再由各系统恢复状态。没有有效存档时禁用加载按钮。
- 每次推进日期、返回主菜单前自动保存。返回时保存失败会保留游戏和当前数据，在 HUD 显示错误，允许重试。
- 料理制作和食用成功后立即保存，食材、食物和体力一起提交。复用已有格子和体力字段；旧存档正常加载，失败可在料理面板或背包中重试保存。
- 完整结束首次 NPC 对话后保存已见面标记，中途退出不记录。失败保留运行中的标记，返回菜单前保存可重试。
- 成功送礼后立即保存背包扣除、好感度和最后送礼日期。写盘失败保留完整运行状态，送礼面板可重试保存，不重复扣除或增加好感度；当天读档仍受每日一次限制。
- 好感度事件完整交谈后保存完成记录，食谱权限由记录推导。失败保留解锁，可在料理面板保存或返回菜单重试，中途取消不记录完成。
- 成功钓鱼后立即保存背包鱼获和体力，售鱼后立即保存库存与金币。版本保持 14，沿用既有字段；抛竿会话不保存。写盘失败保留运行结果，钓鱼 / 商店面板可重试保存。详见 [钓鱼](Fishing.md)。
- 成功存取储物箱后立即保存，背包与箱子库存一起提交。失败保留本次运行的物品分布，面板“保存进度”可重试。
- 工具升级后立即保存，两种材料、金币和工具等级一起提交。失败保留本次运行的升级，面板“保存进度”可重试且不重复付款。
- 采完资源后立即保存，产出、体力和恢复日期一起提交；部分采集次数随普通保存、跨日或返回保存。
- 订单交付后立即保存，扣除作物、发放金币和交付标记位于同一快照；重复点击或当天读档不再发奖励。
- 任务领奖后也立即保存，金币与领奖标记写在同一快照中。保存失败保留本次运行的奖励和标记，重复点击不再次支付，后续跨日或返回菜单可重试。
- 新游戏开始时保留旧存档，第一次自动保存时替换。当前没有多存档选择或退出时保存；直接关闭程序会保留最近一次自动保存的进度。

## 文件与异常处理

路径为 `Application.persistentDataPath/Saves/save.json`；前一次提交保存在 `save.json.bak`。先写同目录临时文件并刷盘，再原子替换正式文件，写入失败不会主动删除旧存档。

读取时校验版本、配置尺寸、农田状态、背包容量、物品 ID、堆叠数量和角色位置。先在临时数据中完成校验，再初始化世界并恢复，避免半恢复状态。

正式文件损坏时尝试有效备份；两个文件都不可用时允许新游戏。版本 1 补初始金币和 06:00 时刻；版本 2 保留金币并补 06:00 时刻；版本 3 保留金币和时间。版本 1–3 补满体力；版本 4 起保留已有体力。版本 1–4 的已种植地块补默认芜菁 ID，当前种子设为默认芜菁种子。版本 1–5 再补天气种子 1 与晴天，迁移到版本 6；版本 5 的混种农田和当前种子保持不变。未知版本拒绝读取。时间必须有限且位于 00:00—24:00，体力必须处于 0 到配置上限之间，作物 ID、种子选择及生长配置必须匹配 CropCatalog；天气枚举必须有效，天气种子必须为正。配置改变导致存档不兼容时也会拒绝恢复，避免静默丢失物品。

版本 1–6 继续迁移到版本 7，补全未开始、未领奖的新手任务；保留世界进度和已存金币，不倒推历史操作或自动发奖励。版本 7 按 TaskCatalog 校验任务 ID、顺序、条目数、进度范围和领奖前置关系；无效任务记录拒绝整份数据。具体规则见 [新手任务](Tasks.md)。

版本 1–7 再迁移到版本 8，为当前总天数生成未交付订单。版本 7 已有的任务进度、领奖标记及金币保持不变，不赠送订单奖励。读取按 OrderCatalog 和季节长度校验种子、日期、订单 ID、物品、数量和奖励，异常订单拒绝恢复。详见 [公告栏订单](Orders.md)。

版本 1–8 继续迁移到版本 9，为当前日期创建完整可采的资源节点。版本 8 的订单、任务和已有物品不被重置，也不发放采集材料。当前版本校验采集节点数量、ID、剩余次数和恢复日期，异常数据拒绝读取。详见 [资源采集](Gathering.md)。

版本 1–9 继续迁移到版本 10，补普通斧头、镐子。版本 9 的采集状态、物品和金币不重置；固定工具数量、顺序及 0 / 1 等级严格校验。详见 [工具升级](ToolUpgrades.md)。

版本 1–10 继续迁移到版本 11，补配置容量的空储物箱。版本 10 的背包、工具等级、资源采集、订单和金币不重置；箱内物品 ID、格子数、数量和堆叠上限严格校验。详见 [储物箱](Storage.md)。

版本 1–11 继续迁移到版本 12，补未见面 NPC，保留既有世界、物品和食物、储物、任务、订单、采集及工具等级。数量、ID、顺序和空记录严格校验，对话当前句不保存。详见 [NPC 与对话](NPCAndDialogue.md)。

版本 1–12 继续迁移到版本 13，补零好感度和未送礼日期，保留 NPC 已见面标记。读取严格校验关系记录数量、ID、顺序、分数范围、送礼日期及见面一致性，未来日期拒绝恢复。详见 [好感度与送礼](Relationships.md)。

版本 1–13 继续迁移到版本 14，补未完成事件，保留已有 NPC、好感度、送礼和世界数据，不按历史分数自动领取食谱。读取严格校验事件 ID / 顺序、完成阈值与前置记录。详见 [好感度事件](StoryEvents.md)。

版本 1–14 继续迁移到版本 15，新增 NPCSchedules，按 NPC 配置顺序记录 ID 与沿路线累计距离，支持途中读档。旧档根据已保存的时刻安排上午 / 傍晚办事处、下午海岸；保留好感度、事件和世界数据。严格检查数量、ID、顺序及有限距离范围。详见 [NPC 日程](NPCSchedules.md)。

版本 1–15 继续迁移到版本 16，新增 PlacedObjects，记录装饰唯一 ID、物品 ID、网格 X / Z 和 90 度朝向索引。迁移补空记录，保留 NPC 日程和全部既有库存 / 世界进度，不赠送装饰。制作、确认摆放和回收成功后自动保存，写盘失败保留运行结果，面板、背包或返回菜单重试；预览不保存。严格校验数量、ID、物品、占位、朝向及农田 / NPC 通道。详见 [制作与摆放](CraftingAndPlacement.md)。

版本 1–16 继续迁移到版本 17，新增 PlayerArea（Island / PlayerHome），现有位置字段在室内按局部坐标保存。成功进出、室内睡觉和其他保存操作同时保存完整世界状态；迁移补 Island，保留既有库存、装饰和 NPC 日程。原床重叠位置恢复到安全门前位置。未知区域、越界及非有限坐标拒绝恢复，加载时检查实际家具。详见 [玩家小屋](Housing.md)。

版本 1–17 继续迁移到版本 18，新增独立 Furniture 数组，保存室内家具的 ID、物品、局部网格位置和朝向。迁移补空家具，不重置玩家区域 / 位置、库存、装饰或其他世界进度。记录在临时状态中校验，实际家具与室内固定布局冲突时拒绝恢复并释放场景；制作、摆放、回收后自动保存，失败保留运行结果并允许重试。详见 [室内家具](Furniture.md)。

版本 1–18 继续迁移到版本 19，新增 HouseUpgrade，记录等级和预定完工日期。迁移补未扩建 / 未施工，不赠送材料、金币或空间，原家具、区域和位置保留。施工中读档不再次扣费；跨日完工先更新几何及家具范围，再保存。按等级校验室内家具和角色位置，非法等级、施工状态及日期拒绝恢复。详见 [小屋扩建](HouseUpgrades.md)。

## 验证

`Tools/VerifySave.cs` 检查快照独立性、格子顺序、恢复后的生长、非法数据拒绝、恢复失败时不修改原状态、原子写入与备份恢复。

`GameFlowVerification.Run` 在独立 Unity 工程和隔离存档目录中验证 AA 新游戏、自动保存、继续游戏、角色位置、保存失败时保留世界、损坏文件恢复和版本拒绝，同时检查 TMP 中文字形和 UI 分层。
