# 存档系统

> 开发前先读根目录 [统一开发约束](../AGENTS.md)。本文保留专项实现与历史演进；旧版本号和旧保存入口描述不代表当前全局规则，现行约束以 AGENTS.md 为准。

游戏进度只在每天睡觉结算后保存，由 GameManager 授权 SaveManager 执行。白天任何玩法操作、面板按钮、场景切换和返回菜单均不写进度文件。设置由 SettingsManager 写入独立文件，详见 [暂停、设置与睡觉存档](PauseAndSettings.md)。

## 保存时间与快照

1. 玩家走到小屋床边，打开休息面板并确认睡觉。
2. GameManager 统一结算出货收入、跨日成长、天气、动物、施工、订单和日报等。
3. SaveManager 捕获完整次日清晨快照，并原子写入本地进度文件。
4. 运行中的日报仍可查看，确认只关闭日报，不再保存；下次读档直接进入已经保存的清晨。

第一次睡觉之前，新局没有存档。点击新游戏不删除或覆盖已有旧档；本局第一次成功睡觉才写入新的进度。

白天农务、购买 / 出售、领奖、订单、升级、储物、料理、食用、对话、送礼、事件、钓鱼、摆放、家具、鸡舍、背包整理 / 拖拽 / 拆分、出货存取只修改当前运行状态，仍遵守各系统原子提交和失败不扣除规则。

返回菜单显示当日进度丢失确认，确认后直接释放游戏。加载游戏恢复最近一次成功睡觉保存的快照；之后的金币、物品、状态和位置变化不会保留。

## 路径与写入

- 进度：`Application.persistentDataPath/Saves/save.json`。
- 备份：`save.json.bak`，保存上一次成功快照。
- 写入临时文件后刷新到磁盘，使用原子替换保留旧文件；失败不破坏此前成功存档。
- 读取先校验主文件，失败时检查有效备份；损坏或未知版本均不会修改运行中的世界。
- 设置：`Application.persistentDataPath/Settings/settings.json`，使用独立备份，不受睡觉限制，也不能改变进度文件。

## 睡觉失败

结算只执行一次。写盘失败时保留已经生成的 JSON 快照和运行结果，日报禁止“开始新的一天”，仅显示“重试睡觉存档”。重试写同一 JSON，不重新捕获当前活动状态、结算收入、扣费或推进日期。

重试成功后隐藏重试按钮，可以确认日报。确认或返回都不再次保存。选择返回将放弃该次未写入的结算，下一次加载恢复此前成功存档。

## 格式与迁移

版本为 29。快照包括农场日期 / 地块 / 作物进度、天气及种子、时钟、体力、选中种子、背包与扩容、金币、任务、订单、采集与海滩剩余物品、工具等级、储物、NPC / 日程 / 关系 / 事件、装饰 / 家具、果树、小屋 / 扩建 / 角色区域及位置、养殖 / 品质蛋、日报和出货箱。

日期、物品 ID、容量与堆叠、等级、生产数量、亲密度、订单池、角色 / 家具位置和日报流水等仍使用原校验规则。出货箱清空、最近结算日期、金币和日报成交明细属于同一睡觉快照，读档不重新发钱。

兼容迁移版本 1–28，保留既有金币、库存和世界状态；缺失系统字段按原迁移补默认值，不补发历史奖励。旧档允许保留其原保存时刻和位置，下一次睡觉后统一改为次日清晨快照。新快照的 DailyReport.Pending 为 false，不必为关闭日报再次写盘。

## 验证

`PauseSleepFlowVerification.Run` 检查实际床边睡觉、白天无文件写入、暂停 / 设置、返回确认、全世界清晨快照、读档丢弃当天变化、日报确认不写盘，以及失败结算的固定快照重试。

`Tools/VerifySave.cs` 检查存档结构、快照独立性、非法记录、原子写入和备份；其他系统的纯规则检查保持有效。较早的编辑器流程中对操作自动保存、直接返回保存和调试跨日的断言属于旧行为，当前集成入口以 PauseSleepFlowVerification 为准。

版本 27 保存品质种子与每格施肥、品质、种植次数，旧农田迁移为未施肥、普通品质，不补发收益。详见 [基础肥料与优质作物](FertilizerAndCropQuality.md)。

版本 28 新增 Orchard，按摆放 ID 保存种植日期与下次结果日期，与物品、金币、摆放记录同时写入。旧档补空记录；树木记录必须与树苗摆放一一对应，非法成长和冷却日期拒绝加载。详见 [果树](Orchard.md)。

版本 29 新增 BeachForage，保存海滩剩余采集物、位置编号、生成日期及种子。跨日补充后随睡觉快照写入，加载和进出场景不补充；旧档在保存当天初始化海滩，已有树石采集状态保持。详见 [海滩拾取](BeachForaging.md)。云层和云影属于天气表现，不写入玩法存档。
