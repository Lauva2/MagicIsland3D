# 优质鸡蛋

当前进度统一在每天睡觉结算后保存；白天操作仅修改运行状态，面板手动保存和返回菜单保存已取消，设置单独持久化。睡觉失败只重试该次固定快照。规则见 [暂停与睡觉存档](PauseAndSettings.md)。

每只鸡当天已喂食，且统一跨日结算时亲密度达到 70，次日有 25% 概率产出优质鸡蛋，否则产普通鸡蛋。每只仍产一枚；未喂的鸡不产蛋。成功喂食的 +2 和当天摸摸获得的亲密度都计入结算。

| 项目 | 普通鸡蛋 | 优质鸡蛋 |
| --- | --- | --- |
| 物品 ID | egg | quality_egg |
| 商店收购 | 25 金币 / 枚 | 40 金币 / 枚 |
| 料理、鸡蛋订单 | 可用，优先消耗 | 普通蛋不足时补足 |

两种蛋均为 AnimalProduct，最多每格 99 枚。生蛋不能直接食用、播种、摆放或送礼。煎蛋和蔬菜蛋汤的产量、体力恢复、送礼规则不变；鸡蛋订单仍收购两枚并支付 70 金币，料理订单的 50 / 90 金币不变。

## 面板与操作

CoopPanel 分别显示待收普通蛋和优质蛋，并说明亲密度门槛和概率。两种待收蛋合计上限 99，喂食前预留产蛋容量。收取全部产物时先模拟两种物品占格，全部能放入才提交；例如只剩一个空格而没有可叠加的蛋堆时，两种蛋都会保留在鸡舍。收取后清空两种数量，巢中产物标记随总量同步。

AnimalShopPanel 显示两种背包数量，提供独立收购卡和“出售一枚”按钮。出售只消耗所选品质，金币溢出或距离不足时不扣物品。

料理、订单面板显示两种蛋合计可用数量。提交时优先扣普通蛋，再用优质蛋补足，缺少其他材料、料理放不下或订单金币溢出时都保留全部材料。通知在完整结果提交后触发，重入请求由对应系统和 GameManager 拦截。操作睡觉时统一保存；失败保留当前结果，可重试保存。

## 框架与存档

AnimalManager 继续负责养殖，由 GameManager 统一初始化、跨日、保存和清理；CookingManager / OrderManager 使用 IngredientResolver 处理食材替代，InventoryState 提供多产物原子添加。普通蛋和优质蛋 ID 从 AnimalConfig 传递，未增加独立 Manager。

AA AnimalConfig 新增 QualityEggItemId、QualityEggPrice、QualityAffinity、QualityChance。默认门槛 70、概率 25%、收购价 40；概率校验为 0–100、门槛为 1–100，优质售价必须高于普通蛋。编辑器仅补缺失物品和字段，完整配置及面板不重复覆盖。UI 继续位于 Art/Prefabs/UI，使用同名 AA 地址、PopUp 层、MVC 和中文 TMP；当前含背包扩容为 21 份配置、24 个 UI 预制体。

存档版本 23 新增 SavedAnimals.QualityEggs 和 QualitySeed。新游戏生成正整数品质种子，结算使用种子、已喂日期和稳定鸡 ID 的固定哈希。每只鸡独立抽取，结算后保存两种实际数量；读档不重抽，重新读取睡前档并重复相同照料也得到相同结果。门槛取结算时的亲密度。

版本 22 及以前迁移时优质待收数补 0、品质种子补 1，已有普通待收蛋、鸡的亲密度 / 摸摸日期 / 喂食日期、库存、金币和已交付订单保持原值；更早版本继续依次执行原迁移。旧档不赠送或转换优质蛋。当前档重复升级保留品质字段。非法种子、负数或超容量的品质数、两种总量加已喂鸡超容量均拒绝，并沿用有效备份恢复。

## 验证

Tools/VerifyQualityEggs.cs 覆盖 4,096 个种子的独立品质结算与睡前 / 睡后恢复、69 / 70 门槛、0 / 100 概率、未喂不产蛋、双品质竞争空格与原子通知、收购价格及金币溢出、合计容量 / 预留、料理和订单普通蛋优先消耗、满背包与缺料、重复交付及版本 22 迁移。默认规则在 8,192 次产蛋中产出 2,083 枚优质蛋。

QualityEggFlowVerification.Run 在隔离 Unity 工程构建并加载 AA，操作真实建造、购鸡、喂食、跨日、收蛋、两种收购、料理和订单按钮；验证中文排版、实际读档固定品质、世界产物标记、保存失败及重试、距离 / 模态 / 重入、真实缺字段的 v22 JSON 迁移、非法品质存档拒绝、清理和新游戏重置。
